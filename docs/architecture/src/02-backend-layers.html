3QUERY
Query / Filtering
AirportDashboardSpecification
Turns optional filters into one dynamic JPA Criteria query — no string concatenation, no query explosion.
notDeleted() — soft-delete guard applied to every query
hasLocation() — case-insensitive LIKE
hasStatus() / hasEntityType() — equality
search() — OR across identifier, name, ICAO, IATA, location, procedure, MITS
Null / blank filters return cb.conjunction(), so absent filters are no-ops
Composed with Specification.where(...).and(...)

5DB
Database
PostgreSQL · airport_dashboard
The only place operational truth lives. Filtering, sorting, counting and paging all execute here.
Partial indexes on status, entity_type, icao, iata, location
Composite index (status, updated_at DESC) for the default table view
All indexes are WHERE is_deleted = FALSE
UNIQUE(entity_identifier) + CHECK constraints on status, type, ICAO / IATA

Error pathGlobalExceptionHandler

  • @RestControllerAdvice intercepts exceptions from any layer
  • Emits a consistent ErrorResponse: timestamp, status, error, message, path
  • Controllers stay free of try / catch blocks

Type mappingconverter package

  • @Converter(autoApply = true) on status and entity type
  • Database stores readable labels ("Pending Calculation"); Java works with enum constants
  • Normalises spacing, case and separators, so legacy rows still load

Caching hookcache + config packages

  • @EnableCaching with RedisCacheManager, 5 minute TTL
  • Summary endpoint is the designated @Cacheable target
  • DashboardCacheService evicts on write via @CacheEvict

API contractdto package + springdoc

  • ApiResponse<T> envelope: success, message, data
  • DashboardSummaryResponse, DashboardRecordResponse
  • Entities never cross the HTTP boundary
  • OpenAPI schema and Swagger UI generated from the controller
Why it matters: each layer can be tested in isolation — the specification without HTTP, the service with a mocked repository, the controller with a mocked service. New filters or endpoints extend one layer at a time.

One request, end to endfiltered + sorted + paged table read

  • Controller binds status=BLOCKED, search=DEL, page=1
  • Service maps the sort key and builds a Pageable
  • Specification composes four predicates into one WHERE clause
  • Repository issues one data query plus one count query
  • PostgreSQL answers from the partial indexes
  • Service maps rows to DTOs; controller returns the envelope
