Data & Cache
PostgreSQL = source of truth   |   Redis = performance layer
Read-heavy workload: the aggregation query is the primary caching candidate

PostgreSQLauthoritative relational store

  • Table airport_dashboard — operational records
  • Audit columns: created / updated / deleted by & at
  • Soft delete via is_deleted; optimistic locking via version
  • CHECK constraints on status, entity type, ICAO / IATA format
  • Partial indexes on filter & sort columns (WHERE is_deleted = FALSE)
  • Summary counts computed in SQL: COUNT(*) GROUP BY status
  • Unique business key on entity_identifier
