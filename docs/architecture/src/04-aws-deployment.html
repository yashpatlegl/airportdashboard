Private subnets · data tier
Amazon RDS for PostgreSQL
System of record
Multi-AZ standby for failover, automated backups and point-in-time recovery. Schema evolution stays with Flyway; read replicas are the first scaling step for reporting.
Amazon ElastiCache for Redis
Cache-aside layer
Holds dashboard summary counts and lookup data with a short TTL. Absorbs repeated aggregation reads; PostgreSQL remains authoritative.
AWS Secrets Manager
Configuration and credentials
Database credentials and Redis connection details are injected into the ECS task at runtime. Nothing sensitive lives in application.yaml or in the image.
Amazon ECR
Container image registry
Immutable, tagged images. The tag deployed to Fargate is the exact artifact that passed CI.

Scaling pathin order of cost and effort

  • Add Fargate tasks behind the ALB — the API is stateless
  • Serve summary counts from Redis to remove repeated aggregation
  • Add an RDS read replica and route dashboard reads to it
  • Move to keyset pagination when deep pages become common
  • Materialise the status summary if counts outgrow live aggregation
  • Introduce a dedicated read model only if the workload demands it
Deliberately excluded: Kubernetes, message brokers, search clusters and serverless functions. Nothing in the current workload justifies them, and each would add operational surface without removing a real constraint.
